# 《晴汐小镇》美术设定与制作规范

与 [游戏方案](01-游戏设计方案.md)、[美术资源清单](03-美术资源清单.csv)、[概念图说明](04-概念图与交付说明.md) 配合使用。

## 本轮风格修订：清透、留白与自然生长

按用户提供的乡间动画截图调整花火主视觉 C01 与场景概念板 C02。保留寿司店与海边小镇设定，以开阔天空、田地、水面和自然村落取代高密度装饰。角色与道具板 C03 本轮不修改，后续制作时再对齐新的环境复杂度。

- **疏密有层次：** 一个镜头只有一个主要焦点；建筑、路边和台面保留没有装饰的面积。完整资产库的数量不等于每个镜头必须摆满这些资产。
- **环境更可信：** 房屋疏落、路面朴素，采集点与普通草地分开；不用花海、爬藤、盆栽和灯笼填满所有空处。建筑以生活用途与地形关系组织。
- **菜园有真实生长状态：** 近景菜畦约 35%–45% 可留为未播种、间苗或采收后的裸土；同一类菜也有幼苗、半成株和成熟株，叶片角度、朝向和间距有变化。变化不能妨碍玩家判断收获状态。
- **距离影响细节：** 前景保留关键轮廓，中景减少叶片和纹理噪声，远景降低对比和饱和度、偏向环境色并柔化边缘。优先做空气透视，再少量增加景深；不能靠全图模糊代替空间层次。
- **清新来自光与色：** 白天保留自然蓝天和青草绿；暖光用于局部，不给整张图统一覆盖金橙滤镜。木材与灰泥减少高频浮雕和油亮反光。
- **花火以尺度形成高潮：** 平静海面与开阔天空作为基底，以一朵主花火和少量错开的次花火形成重点。演出可连续变化，单帧不必塞满所有颜色与粒子。

### 修订后的验收镜头

1. 把画面缩小后，仍能看出主要焦点、宽阔安静区和近中远层次。
2. 菜园同时看得见大小不同的作物、空畦和采收缺口，不出现整片等大复制蔬菜。
3. 远山与远屋不与近景争夺锐度；钓鱼浮标、入口和作物成熟状态仍清楚。
4. 寿司台面有连续可用的空操作区，墙与窗周围保留素面。
5. 花火画面中，观景者、海面反光与主花火形成清楚关系，不被满屏装饰分散。

## 1. 视觉支柱

1. **天空有情绪。** 用清楚的大云形、空气透视和逆光边缘表达季节。白天清亮，夕阳杏桃，夜晚深靛；花火是明度和饱和度的峰值。
2. **比例可爱，生活可信。** 成人约 4.5 头身，儿童约 3.5 头身；建筑边缘轻微圆润，工具能握、厨房能走、家具能坐。
3. **经营结果看得见。** 门帘、菜单、盛器、座位、会场灯笼随着进度改变；升级以少量关键变化呈现。
4. **小细节聚焦。** 让水珠、米粒、木纹和风铃在近景出现；远景使用清楚的块面，避免满地图高频纹理。

## 2. 色彩与材质

| 色彩 | 色值 | 用途 |
|---|---|---|
| 米白 | #FFF0D6 | 墙面、纸张、界面底色 |
| 海玻璃青 | #86C8C0 | 门帘、标志性物件、部分夜间花火 |
| 杏桃珊瑚 | #ED967E | 配件、夕照、灯笼高光 |
| 暮色靛蓝 | #344F79 | 工作服、阴影、夜空 |
| 鼠尾草绿 | #91AC8A | 农园、植物中间色 |
| 蜂蜜木色 | #B98A5A | 柜台、家具、建筑木构 |

材质以哑光木、柔和灰泥、绘制陶瓦、布料与局部亮面食物为主。金属只在刀具、灯座等位置少量出现。水体能读出深浅和鱼影；不追求照片级折射。界面与场景保持至少两类非颜色线索，如图标形状和文字提示。

## 3. 人物与服装

- 主角先做一套兼容骨架的成人基础体，概念默认短栗发、米白上衣、靛蓝围裙、珊瑚方巾。完整角色自定义再扩至两种轮廓体型、六款发型、八套服装；不使用仅靠肤色区分的复用人物。
- 村民先做剪影并列检查：渔师轻便、菜农宽帽、花火师直线工作服、木工腰间工具、馆长柔软针织。每人有正侧背转面、表情、手部持物和色板。
- 成人共享基础动作；儿童、老人和猫保留对应步幅。先用体型缩放确认比例，再修正穿模和脚底滑动。
- 表情以眉、眼、口三个层级组合；首个版本不用昂贵全脸捕捉。重要对话有微笑、担心、惊喜、沉默、眺望五类情绪。
- 通用顾客用可替换头发、上衣、下装组合，避免把十位具名村民直接当背景克隆。

## 4. 场景构图与可玩尺度

统一 1 单位 = 1 m。门净高约 2.1 m，主路宽 3–5 m，支路宽 1.5–2 m。室内走道净宽至少 0.9 m，经营主通道建议 1.2 m；以角色碰撞与镜头测试为最终标准。

### 关键场景制作卡

| 场景 | 画面锚点 | 构图与交互重点 | 避免 |
|---|---|---|---|
| 寿司店外 | 薄荷门帘、一至两盏灯、素木招牌 | 桥边能一眼识别入口，墙面和门前保留素净空间 | 花草、灯笼与招牌堆满立面 |
| 寿司店内 | 木柜台、玻璃食材柜、米饭蒸汽 | 8 个吧台席与 2 张小桌为完整版本布局；原型先启用部分座位 | 柜台后无通路、镜头被梁遮挡 |
| 河岸钓点 | 浅水鱼影、圆石、木栈台 | 出竿方向清楚，岸边有站位安全区 | 草叶遮住浮标、强反射遮鱼 |
| 农园 | 菜畦、竹篱、工具棚 | 幼苗、成株和空畦并存，湿土与成熟状态清楚 | 等大植株铺满网格、全靠颜色判断成熟 |
| 玩家小屋 | 低窗、坐垫、小桌、海景 | 墙体可淡出，家具插槽与网格仅装修时显示 | 装饰影响人物出入口 |
| 祭典会场 | 灯笼路径、摊架、海湾开口 | 日间布置与晚间演出共用地形，保留多处观景点 | 发射点与人群同处近景 |

店铺、住宅与商店共用柱、梁、墙、窗、屋顶和台阶。地面材质至少有泥、草、石、水边四类过渡。海岸和山林用远景代理延伸世界，不把所有可见山体做成可走地形。

## 5. 四季、天气与昼夜

地形和建筑复用一套主结构，以植被变体、地表材质、装饰覆盖和光照配置实现变化。春花、秋叶、冬霜不能只靠整体调色；物候明确但每种植物不必四季重做模型。季节物集中在少量位置，保留普通草地、裸土与素面，避免所有边缘都铺花或落叶。

日照关键状态：清晨、正午、黄昏、蓝调、深夜。室内通过可控暖光与窗外色温形成对比。天气先实现晴与雨；雾和雪属于完整版本。水面反射优先保证普通镜头可读，在性能允许时逐级增加效果。

花火使用可控序列、粒子、光晕和水面假反射组合；峰值时限制同时存在的高成本透明层。声音具有远近层次。低闪烁模式以柔和绽放和更长渐变替换频闪，保留高潮节奏。

## 6. 料理与自然物的辨识

料理采用放大关键特征：米团形状、鱼片油光、紫苏叶缘与腌萝卜切面；不逐粒建米。菜单图可以用渲染图加工，但需要最终人工排版与准确名称。

自然物先看剪影：海鱼纺锤、河鱼细长、蝴蝶张翅、甲虫圆壳、蝉的收翅。可食野菜使用醒目的形状组，采集和不可采集植物同时有交互标记。资源图鉴为游戏设定，不提供现实采食鉴定依据。

## 7. 实时资产规格：作为原型起点

引擎尚未确定。以下是 PC 风格化独立游戏的暂定预算，单位与工具链确定后再锁定；不是跑过性能测试的结论。

| 类别 | LOD0 建议三角面数 | 纹理起点 | 约束 |
|---|---|---|---|
| 主角 | 15k–25k | 2K 主贴图组 | 可替换头发与服装，体型共用绑定规则 |
| 具名村民 | 10k–18k | 1K–2K | 成人尽量复用骨架，表情另计 |
| 猫 | 5k–9k | 1K | 跑、坐、伸懒腰，尾巴骨骼 |
| 建筑外观组合 | 15k–40k/可见组合 | 2K 图集/平铺 | 按模块拆，室内外分离 |
| 小道具 | 100–2k | 256–1K/共享图集 | 多个小物共图集，少材质槽 |
| 家具 | 1k–8k | 512–1K | 摆放碰撞、吸附点、可交互标签 |
| 食物 | 500–3k/盘 | 512–1K 图集 | 近景和菜单图验证食欲感 |
| 鱼/昆虫 | 300–3k | 256–512 图集 | 实体展示与收集展示共用 |
| 树 | 2k–8k | 1K–2K 图集 | LOD、风动、阴影控制 |

角色建议三档 LOD，环境物按占屏尺寸生成 LOD 和远景代理。透明材质用于叶片、门帘边缘和特效时控制叠层。目标 1080p/60 fps，以中档 PC 为暂定方向；基准硬件与真实预算在引擎原型阶段指定，不能在没有实测时声称达标。

## 8. 命名、源文件与交付

命名示例：`CHR_Player_A`、`ENV_Sushi_Wall_A`、`PRP_Net_A`、`FOD_Nigiri_Aji`、`VFX_Firework_Gold`、`UI_Icon_Fish_Aji`。具体路径建议：`Art/Characters`、`Environments`、`Props`、`Food`、`VFX`、`UI`；未选引擎前只作为工作约定。

每项正式资产交付：可编辑源文件、通用交换文件、贴图、材质说明、预览图、尺寸/轴向、碰撞、绑定及动画清单、LOD、授权来源。模型坐标和导出轴向随引擎统一；不要在未定引擎前混用导出设置。

关卡验收用固定镜头截图：正午外景、黄昏外景、雨天、店内、夜市、花火峰值；同时提交碰撞和导航测试记录。字体使用具有适当授权的中文字体，招牌文字由设计师排版，不能把概念图中的伪文字直接作为最终资源。

## 9. 制作顺序与风险

1. 灰盒验证尺寸和摄像机 → 2. 玩家与寿司店风格样片 → 3. 三个原型区与必要道具 → 4. 五道菜与收集物 → 5. 人物事件与花火短序列 → 6. 性能和清晰度测试 → 7. 扩展四季、区域和家具。

最大成本来自 NPC 内容、四季变体、室内装修组合和经营动画。先让成人共骨架、环境模块化、季节覆盖复用；菜谱数量固定，不让自由配方无限增加模型。列表中的数量是制作估算，未包含返工、外包管理、文本本地化和音频制作成本。

概念图用于方向沟通，不能直接当作可操作的 3D 地图、已绑定角色或生产级贴图。最终模型以尺度、连通性和交互规则为准；发现概念图与玩法冲突时先修正灰盒。
